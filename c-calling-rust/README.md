# C Calling Rust Static Library

This project keeps native Rust code separate from the C ABI boundary:

- `rust-lib/src/calculator.rs`: native Rust logic.
- `rust-lib/src/text.rs`: native Rust text helpers.
- `rust-lib/src/geometry.rs`: native Rust geometry types and operations.
- `rust-lib/src/numbers.rs`: native Rust numeric aggregation logic.
- `rust-lib/src/ffi.rs`: thin `extern "C"` wrappers only.
- `rust-lib/src/lib.rs`: crate module wiring and Rust tests.
- `main.c`: C caller that includes the generated header.

Build the debug artifacts:

```sh
make
```

Build the release artifacts:

```sh
make PROFILE=release
```

Generated artifacts are profile-specific:

- Header: `rust-lib/target/<profile>/include/rust_lib.h`
- Static library: `rust-lib/target/<profile>/librust_lib.a`
- C demo binary: `rust-lib/target/<profile>/c-calling-rust`

The header is generated by `cbindgen` from the Rust ABI declarations during `cargo build`.

Current FFI examples:

- Scalar arguments and return value: `rust_lib_add`.
- C string borrowed by Rust: `rust_lib_c_string_len`.
- Rust-allocated C string returned to C: `rust_lib_greeting_new` and `rust_lib_string_free`.
- C-compatible struct passed by value: `rust_lib_point_distance_from_origin`.
- C array borrowed by Rust: `rust_lib_sum_i32`.
- C-owned output struct filled by Rust: `rust_lib_analyze_i32`.
